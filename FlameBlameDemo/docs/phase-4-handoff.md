# Фаза 4 — підготовка здачі та віха стабільності

## Реалізовано

- Меню Configure WebGL / Validate Submission / Build WebGL / Build Windows, batch-методи `FlameBlame.EditorTools.SubmissionBuild.*`.
- WebGL: Brotli з JavaScript fallback, без кешу IndexedDB, хешовані назви файлів, DXT, Managed Stripping Low, WebGL 2, пам’ять 256–1024 МБ, Run In Background. Canvas підлаштовується під вікно; pixel ratio обмежений 1.5.
- Windows: x64, Mono, вікно 1280×720 зі зміною розміру; низький stripping.
- Адаптивна емісія: пороги 40/55 FPS із гістерезисом, кроки зниження/відновлення, мінімальна якість 0.35, відсікання після 18 м. Налаштування порогів/дистанції — ChaosSettings; вимірюється unscaled frame time. Фізика води, електрика й нагрівання не залежать від емісії.
- Runtime-жорсткі межі пулів і частинок: jet ≤240, flame ≤16×36, steam ≤6×12, splash ≤8×10, spark ≤4×8. Разом ≤1000 для авторських систем сцени.
- Виправлено видимість повторно взятих із пулу ефектів після дистанційного відсікання, повернення захоплення курсора кліком після Esc; назва предмета для звіту про шкоду кешується на старті. Числові поля HUD попередньо прогрівають mesh-буфери.
- README для суддів; VIDEO_SCRIPT на 4:35; AI_LOG містить рівно два речення. Детальна історія перенесена в AI_HISTORY.
- `tools/serve-webgl.mjs`: локальний сервер без npm-залежностей; `tools/package-build.ps1`: архіви з ліцензіями й без Burst DoNotShip debug-файлів.

## Перевірки

Unity 6000.3.24f1. Відсутній WebGL Build Support завантажено з офіційного сервера Unity; Authenticode-підпис Valid, Unity Technologies SF; модуль встановлено до відповідної інсталяції.

19/19 наявних EditMode-тестів пройшли (`Logs/phase4-tests.xml`). Перевірка Main підтвердила посилання композиційного кореня, 1000 частинок місткості відомих шаблонів і одне джерело тіней. Окрема Windows-версія стартувала без зафіксованих runtime-винятків у headless startup smoke.

Аудит вихідного коду не виявив runtime Shader.Find або reflection; Instantiate виконується під час прогрівання пулів, гарячі фізичні запити використовують NonAlloc або одиночний SphereCast. Observer-підписки мають відписки; стан не зберігається в singleton. Незалежний read-only review не знайшов Critical/Important проблем. Це аудит власних шляхів коду, а не обіцянка нульових алокацій усередині Unity/TMP без профайлера.

Обидва фінальні BuildReport мають Succeeded, 0 errors / 0 warnings: WebGL 13 675 074 байти, Windows 95 798 443 байти. Звіти збережено в `docs/verification/build-*.json`; останній журнал WebGL — `Logs/phase4-webgl-shadow.log`.

Повний Chrome headless smoke завантажив WebGL, показав воду, дійшов до результату та натиснув кнопку рестарту: новий кадр має двох NPC, початковий рахунок $62 від стартової пожежі й новий таймер. Зафіксовано 0 JS-винятків і 0 Lit draw errors на 538 874 Lit-викликах. Підсумок — `docs/verification/browser-smoke.json`; кадри — `Captures/phase4-webgl-{play,result,restart}.png`.

Браузерна перевірка виявила й допомогла виправити реальну платформну проблему: у Mobile URP-профілі вимкнена підтримка додаткових тіней залишала `_AdditionalLightsShadowmapTexture` з compare mode NONE при активному `sampler2DShadow`. WebGL відхиляв Lit draws через INVALID_OPERATION, тому кімната зникала. Configure WebGL тепер вмикає підтримку порожньої comparison-depth текстури; усі додаткові ліхтарі лишаються без тіней. Після повторної збірки кімната/руки/NPC відображаються, sampler mismatch відсутній. SRP Batcher залишено ввімкненим; RenderGraph не вимикався.

Headless Chrome не підтримав нативне захоплення миші в цьому оточенні: для smoke підмінено лише `requestPointerLock` у перевірочному сеансі. У продукті підміни немає. Залишилися стартові повідомлення Unity про перевірку непідтримуваних internal formats, неактивні debug-шейдери та завантаження звуків; вони не спричинили JS-винятків у цьому проході. Нативний pointer lock, гучність, тривала стабільність і FPS потребують звичайного ручного Chrome-проходу.

## Запуск

З кореня репозиторію:

```powershell
node tools/serve-webgl.mjs
```

Chrome: http://127.0.0.1:8080. Натисніть «Завантажити гру», потім у canvas. Esc звільняє мишу, клік у грі захоплює її знову. Сервер прив’язаний тільки до localhost. Для зупинки — Ctrl+C у вікні власноруч запущеного сервера; поточний фоновий локальний сервер можна зупинити через диспетчер задач.

Збірка: відповідний пункт меню або batch-приклад у README. Архівування після збірки:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File tools/package-build.ps1 -Target WebGL
powershell.exe -NoProfile -ExecutionPolicy Bypass -File tools/package-build.ps1 -Target Windows
```

ExecutionPolicy застосовується лише до цього процесу; системна політика не змінюється. Пакування не публікує й не надсилає файли.

## ЗРОБИ ВРУЧНУ — ВІХА 4

1. Пройдіть WebGL у Chrome на цільовому ПК **2–3 рази від старту до результату**, кожного разу натискаючи «ЩЕ РАЗ». Перевірте, що новий раунд має двох NPC, а рахунок скидається до початкового стану: перші збитки від стартової пожежі можуть з’явитися одразу.
2. У проходженнях перевірте Space, віддачу, перегини рукава, кидання й підбирання ввімкненого брандспойта, гасіння/пару, калюжі/кабель/удари, звук, Esc/повторний клік. Спробуйте змінити розмір вікна та перейти на іншу вкладку й назад.
3. Тримайте відкритою консоль Chrome DevTools: зафіксуйте нові помилки та помітні просідання. Перевірте нормальне захоплення миші й активацію звуку без headless-обхідних шляхів.
4. Підтвердьте «ок» або надішліть конкретний сценарій відтворення проблеми. До цього фінальна стабільність не вважається прийнятою.
5. Запишіть відео за VIDEO_SCRIPT.md, перевірте тривалість ≤5 хв, читабельність і гучність.
6. Після погодження надішліть через конкурсного бота відео, WebGL/Windows архіви або посилання на них і два речення з AI_LOG.md. Бот і публічний хостинг не налаштовані цим проходом.

Жоден headless smoke не замінює людську оцінку відчуття, аудіобалансу та FPS на RTX 3060. Відео та відправку не виконано.
