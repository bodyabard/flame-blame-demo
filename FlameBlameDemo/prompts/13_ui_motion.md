# Фаза 13 — UI: скруглені форми й motion design

Прочитай `CLAUDE.md`. Референси стилю: `Reference/11_logo_ui_palette.jpg` (товсті контури, червоно-оранжеві тони, грайливість), готові спрайти в `UI_Sprites/` (див. `UI_Sprites/README.md` і `_preview.png`).

## Проблема
Зараз усі плашки HUD — суворі прямокутники без контуру й тіні, а підказки — довгий рядок тексту внизу. Анімацій немає: значення просто змінюються. Для критерію «Смак» це слабко.

## Мета
Скруглені «мультяшні» плашки з контуром, тінню й легким відблиском. Іконки. Манометр зі стрілкою. Підказки клавішами. І **motion design**: кожна подія гри помітна в UI (поп, пружина, відлік, тряска), але нічого не заважає грі.

## Не чіпати
Ігрову логіку, post-processing, світло, сцену. Лише Canvas, UI-префаби, презентери UI й система твінів.

---

## 1. Імпорт спрайтів
1. Скопіюй `UI_Sprites/*.png` у `Assets/_Project/Art/UI/Sprites/` (без `_preview.png` і `_tools/`).
2. Editor-скрипт `Tools/FlameBlame/Import UI Sprites`: Texture Type = Sprite (2D and UI), Mipmaps OFF, Wrap = Clamp, Filter = Bilinear, Compression = None або High Quality. **9-slice borders** читай з `UI_Sprites/sprites_meta.json` (формат `[L, B, R, T]` → `spriteBorder = new Vector4(L, B, R, T)`). Для `gauge_needle` виставити pivot `(0.5, 0.06)`.
3. Якщо потрібні нові форми чи іконки, генеруй їх тим самим скриптом `UI_Sprites/_tools/gen_ui_sprites.py` (Python + Pillow, білі, supersampling ×4, ті самі радіуси й товщини контуру), щоб стиль був однаковий. Не малюй UI-форми через кастомні шейдери.

## 2. Візуальна система
- **`UIPanel` префаб** (шари знизу вгору): `panel_shadow` (зсув (4, −8), Sliced) → `panel_fill` (тінт кольору) → `panel_gloss` → `panel_outline` (тінт `#2B1410`). Те саме для `UIPill` і `UIKeycap`.
- **`UIPalette`** (ScriptableObject): fill `#D63E24`, outline `#2B1410`, accent `#FFC23C`, text `#FFF0DC`, water `#6EC8FF`, jet `#FFAA3C`, shock `#FFE03C`, danger `#FF3B2F`. Усі кольори UI беруться звідси.
- **Текст:** наявний TMP-шрифт (з кирилицею). Додай матеріал-пресет: **Outline** темний (`#2B1410`, ~0.2) + **Underlay** (тінь вниз ~2 px). Цифри можуть бути трохи більшими й жирнішими за підписи.
- **Грайливість:** верхні плашки нахилені на ±1.5–2° (у різні боки), як наліпки. Не більше.
- **Canvas:** Canvas Scaler — Scale With Screen Size, 1920×1080, Match 0.5. Перевір читабельність при 1280×720 (WebGL embed на itch).
- **Продуктивність:** окремі Canvas для статичного й для анімованого (щоб анімації не перебудовували весь HUD); `Raycast Target` OFF на всьому неінтерактивному; без Layout Group на анімованих елементах.

## 3. Елементи HUD (переробити)
| Елемент | Де | Склад |
|---|---|---|
| **Збитки** | верх-ліво | `UIPanel` + `icon_coin` (акцент) + число `$0` |
| **Час** | верх-право | `UIPanel` + `icon_clock` + `97 с` |
| **Манометр тиску** | низ-право | `circle_fill` (темний) + `gauge_ring` Filled Radial (колір від тиску: вода → акцент → danger) + `gauge_needle` + `43%` під ним |
| **Індикатор режиму** | біля манометра | маленький `UIPill` з `icon_water` (гасіння) або `icon_jet` (тяга) |
| **Підказки клавіш** | низ-центр | замість довгого рядка — ряд `UIKeycap` з літерою + короткий підпис: `ЛКМ вода` · `Q режим` · `E кинути` · `F драбина`. Показуй лише актуальні для поточного стану (несеш драбину, на драбині, в польоті тощо) |
| **Контекстна дія** | центр, трохи нижче прицілу | `UIKeycap` + `UIPill` з текстом: «F — взяти драбину», «F — поставити» тощо |
| **Попапи збитків** | у точці події на екрані | `burst` (акцент) + `UIPill` «Диван −$1200» |
| **Банер** | центр-верх | великий `UIPill`: «Злети до вікна!», «ПОЖЕЖА! 120 с», «РЕЖИМ ТЯГИ» |
| **Екран результату** | центр | великий `UIPanel`, заголовок, рядки статистики з іконками, кнопка «Ще раз» (`UIPanel` як кнопка) |

Правило електрики «Вода + кабель = …» і «Жовті калюжі небезпечні» показуй **один раз** банером на старті (кілька секунд), а не постійним рядком.

## 4. Motion design

### 4.1 Рушій твінів (без залежностей)
Напиши власний легкий `UITweenRunner` (а не DOTween), щоб не додавати пакет і контролювати алокації:
- твіни як `struct` у попередньо виділеному масиві; один `Update`; **нуль алокацій** при запуску й під час роботи;
- `unscaledDeltaTime` (UI анімується й на паузі/екрані результату);
- easing: `OutCubic`, `OutBack`, `OutElastic`, `OutBounce`, `InOutSine`, `Linear`;
- канали: `anchoredPosition`, `localScale`, `localRotation.z`, `CanvasGroup.alpha`, `Graphic.color`, `Image.fillAmount`, довільне `float` через делегат-кеш (для лічильників);
- `Punch` (затухаюча осциляція) і `Shake` (шум з затуханням) як окремі хелпери;
- скасування й перезапуск твіна на тому ж каналі (щоб часті події не накопичувались);
- **`Spring`** (недодемпфована пружина) для стрілки манометра й лічильників.
- Тривалості, easing і сили — у `UIMotionPresets` (ScriptableObject), щоб я тюнив без коду.

### 4.2 Каталог анімацій
| Подія | Анімація |
|---|---|
| **Старт раунду** (влітання у вікно) | Банер «ПОЖЕЖА!» влітає зверху (`OutBack`, 0.35 с), тримається 1.2 с, вилітає. HUD-плашки виїжджають із-за країв екрана з затримкою 0.06 с між собою (`OutBack`) |
| **Збитки зросли** | Число «докручується» до нового значення (0.4 с, `OutCubic`), плашка `Punch` scale (1 → 1.12), монета робить оберт (scaleX 1→−1→1), короткий спалах кольору в акцент. Великий удар (> порогу) дає сильніший punch + `Shake` плашки |
| **Попап збитків** | Поява в екранній точці події: scale 0 → 1.1 → 1 (`OutBack`, 0.25 с), `burst` за ним повільно обертається й тьмяніє, підйом на ~60 px за 0.9 с, fade. Пул попапів (6–8) |
| **Таймер** | Кожну секунду легкий «тік» (scale 1.04 → 1). Останні 15 с: колір → danger, «пульс» щосекунди. Останні 5 с: + легкий `Shake` |
| **Тиск** | Стрілка й кільце йдуть до значення через **пружину** (видно перехльост). Падіння тиску від перегину: червоний спалах кільця й тремтіння манометра. Високий тиск: мікро-тремтіння стрілки |
| **Перемикання режиму (Q)** | Іконка в пілюлі «перевертається» (scaleX 1 → 0, заміна іконки й кольору, 0 → 1, разом 0.25 с), пілюля `Punch`. Коротко з'являється банер «РЕЖИМ ТЯГИ» / «РЕЖИМ ГАСІННЯ» (0.8 с) |
| **Контекстна підказка** | Поява pop-in (`OutBack`, 0.2 с), у спокої м'яке «дихання» (scale 1 ↔ 1.03, 1.2 с). При натисканні клавіші keycap «сплющується» (scaleY 0.85 → 1) |
| **Підказки клавіш** | Зміна набору: старі fade/slide вниз, нові з'являються з невеликим stagger |
| **Удар струмом** | Жовтий спалах по краях екрана (окремий full-screen `Image` з радіальним градієнтом, генеруй спрайт тим самим скриптом) + `Shake` усього HUD 0.3 с |
| **Падіння з драбини / жорстке приземлення** | Короткий `Shake` HUD (слабкий) |
| **Екран результату** | Затемнення фону (fade 0.3 с), панель падає зверху (`OutBounce`), рядки статистики з'являються по черзі з «докручуванням» чисел, кнопка «Ще раз» «дихає», hover → scale 1.06, натискання → сплющування |

### 4.3 Правила руху
- Тривалості 0.15–0.45 с (банери до 1.5 с утримання). Overshoot — так, затяжні анімації — ні.
- Анімації **ніколи не блокують ввід** і не затримують ігрову логіку.
- Одночасно не більше 2–3 помітних анімацій у фокусі; дрібні (тіки) не конкурують із важливими (збитки, режим).

## 5. Архітектура
- Презентери (View) підписуються на події через існуючий Observer (`IGameEvents`): `DamageDealt`, `PressureChanged`, `NozzleModeChanged`, `RoundStarted/Ended`, `TimerTick`, `NpcShocked`, `LadderPlaced`, `InteractableFocused/Unfocused` тощо. Якщо потрібної події немає, додай її в `IGameEvents` (без опитування в `Update`, без прямих посилань UI → геймплей).
- Розділ: `UIPanelView` (вигляд), `*Presenter` (реакція на події), `UITweenRunner` (рух). Без Singleton: раннер і пресети ін'єктуються через `GameBootstrap`.
- Нуль алокацій у кадрі: форматування чисел без `string.Format`/конкатенації щокадру (кешуй рядки або оновлюй текст лише при зміні значення, `TMP.SetText` з числовими аргументами).
